## 关键设计决定

- **均衡算法**:按 rank 升序,每 G 人一批,批次间 `1..G` 正序 / `G..1` 逆序交替;
  批内在「一组建一人」约束下求 `性别差² + 班委数²` 最优排列 —— n≤7 穷举全排列(最多 5040 种),
  更大规模退化为逐槽贪心。**代价相同时保留恒等排列** ⇒ 无性别/班委信息时严格等于「按排名顺序分配」。
- **班委识别**靠标签文本(`CADRE_KEYWORDS`:班长/委员/课代表/组长/monitor…),
  没有新增独立字段 —— 避免再加一个需要用户维护的属性。
- **diff 签名**:`seat-grid` 原来只比 `studentId`,排名/标签在 studentId 不变时不会重绘。
  新增 `innerSignature()`(rank+gender+tags)参与 diff,顺带修掉「改标签后座位图标不刷新」的老问题。

# 第二次迭代 —— 名单按排名呈现 / 配对搜索 / 按组聚座 / 均衡系数

## 需求
1. 所有出现学生姓名列表的界面、以及导出名单/Excel，默认按排名顺序；
2. 配对设置的选择学生框改为可输入姓名搜索；
3. 「按排名均衡分组」时**同时**按组聚座（同组坐成矩形块，行列数相差尽量 ≤2）；
4. 分组设置 / 分组模式下显示各分组的「均衡系数」，便于手动调整。

## 实现
- **名单排序**收敛到两个出口：`getUnassignedStudents()` 内部 `sort(compareByRank)`；
  `getStatContext()` 结尾统一 `list.slice().sort(compareByRank)`（复制姓名与 Excel 共用同一上下文）。
  Excel 首列加「排名」，`!cols` 同步加宽。座位 CSV 保持按座位视角，不参与排名排序。
- **配对搜索**：把 4 个 `<select>` 换成 `<input list="pairStudentSuggestions">` + 原生 `<datalist>`；
  `resolvePairStudent()` 做「精确姓名 → 唯一片段（自动补全）→ 多命中/无命中 alert」三态判定；
  回车即添加、添加后清空并把焦点放回 A，方便连续录入。
- **按组聚座**：新增 `modules/group-layout.js`（纯几何）：
  `chooseBlockShape` 在 `bh×bw ≥ 最大组人数` 的候选里按
  `4·空位 + 形状惩罚 + 0.5·总行数 + 0.4·右侧余列` 取最优（形状惩罚基于**实际占用**行列差，
  超 2 重罚；代价差 ≤0.5 时优先更宽 ⇒ 6 人 6 组得 `2×3`）；
  `planGroupSeatSlots` 块按「左→右、上→下」分配、块内 row-major、跳过 blocked、
  铺不下块时退化为顺序连续排。
  主 IIFE `arrangeSeatsByGroup()`：清出待移动学生（未分组锁定）→ 容量检查 → 规划 →
  **就地写回 `currentSeats`** → `commit + generateSeats + generateStudentList + autoSave`。
  入口两处：均衡分组后自动聚座 + 分组设置新增「按组聚座」按钮（可撤销，`pushSnapshot('arrange')`）。
- **均衡系数**：新增 `modules/group-balance.js`，三维加权（排名 0.6 / 性别 0.2 / 班委 0.2，
  缺数据自动剔除并归一）。展示：分组行 `.group-balance-badge`（good/fair/poor 三色）、
  分组设置顶部整体汇总（整体分 + 极差 + 最弱组）、分组模式 banner 按钮内徽标；
  `title` 给出逐维度分数 + 男X/女Y + 班委数 + 平均排名。

## 关键决策：排名维度必须用「排名带覆盖度」
第一版用的是「组平均排名 vs 全班平均」的 z 值。单测立刻暴露盲区：
把 18 人按名次整块切成 3 组（1-6 / 7-12 / 13-18），中间那组均值恰好等于全班均值 ⇒
rankScore = 100，指标完全看不出问题。
改为**排名带覆盖度**：按 rank 排队、每 G 人切一条带（G = 非空组数），蛇形分组的理想形态正是
「每条带每组各一人」；逐组算 `dev = Σ|c_b − bandSize_b/G|`，`score = 100·max(0, 1 − dev/(2k))`。
整块切分三组都掉到 33.3 分，蛇形分组接近 100 分 —— 盲区消失。
**教训**：设计「均衡/健康度」指标时要先自问「哪种坏情况会被它判成好」。

# 第四次迭代 —— 区域设置(九宫格) + 配对候选自绘下拉

## 需求
1. 4 个配对选择框的候选列表：把「第几名」放到名字右侧、压扁列表项 ⇒ 一屏看到更多候选；
2. 智能排座新增「区域设置」：可逐生设置「倾向区域 / 避开区域」，排座时尽量把该生安排进 /
   不安排进 9 个区域中的某一个（前左…后右）。

## 实现
- 新增 `modules/zone.js`（纯函数，224 行）：`ZONE_DEFS/ZONE_IDS`、`bandIndex`、`seatZone`、
  `buildZoneMap`、`studentZonePrefs`、`zoneCost`、`zoneStats`、`optimizeZones`。
  区域 = 行三等分 × 列三等分；`total===1→中`、`total===2→前/后`，避免空档。
- `optimizeZones` 做**等价换座**（有人↔有人），代价「倾向未达成 +2 / 避开命中 +3」，
  收益必须严格 >0 才换，最多 4 轮；硬约束通过调用方注入的 `guard` 判定。
- `random-arrange.js` 在 `commit()` 之前、性别收尾修复之后调用；
  guard 四道：回避同桌 → 是否旧座位 → 性别规则 → 配对违规数不上升。
  返回值增加 `zone: zoneStats(...)`，主 IIFE 用 `MESSAGES.ZONE_RESULT(met,total)` 出 toast。
- UI：智能排座下拉新增「区域设置」菜单项（角标 = 已设置人数）→ `.zone-popup`（复用 `.pair-popup`）：
  3×3 预览（带 n 想坐 / n 避开 计数）+ 姓名过滤 + 「姓名/排名/倾向/避开」四列表头 + 逐行两个 select。
  改动即时写 `zonePref/zoneAvoid` + `autoSave()`；倾向=避开 会 alert 并回退。
- 配对选择框：`<datalist>` 全部换成自绘 `.pair-suggest`——姓名左、第N名右、行高 24px、
  最大高度 192px（8 项）；支持输入过滤（姓名子串 / 名次前缀）、↑↓、Enter、Esc、点选；
  点选后把学生 id 记到 `input.dataset.studentId`，同名也能区分。

## 踩坑
1. 原生 datalist 的 `label` 由浏览器渲染，既不能把名次放右侧也压不扁；**换成自绘列表**才能满足
   「一屏更多条」。
2. 自绘列表不能用 `click` 选（`blur` 会先把列表收起）⇒ 用 `mousedown` + `preventDefault`。
3. 自绘列表不能做绝对定位浮层：父级 `.pair-popup` 有 `overflow-y:auto`，会被裁掉 ⇒ 改成就地撑高。
4. 单测初版把 1 行 3 列的座位当成「前左/前中/前右」，实际 `bandIndex(0,1)=1` ⇒ 是「中左/中中/中右」。
   边界档位的语义要写进测试名，否则自己都会被绊。
5. batch27 里「避开」断言天然带运气成分（9 人 9 座，某区域只有 1 个座位）⇒ 只作为附加检查，
   主保证交给 `unit_zone`（G2 是确定性的）。
6. 开「男女同桌」后区域偏好可能达不成（抢同一批座位）⇒ 这是**设计正确的降级**，
   测试断言应校验「0 桌性别违规 + 全员入座」，而不是硬要求偏好达成。
