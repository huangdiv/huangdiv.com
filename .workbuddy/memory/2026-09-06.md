## 随机排座 bug 修复(commit e9a13e4,推送中)

**Bug**:用户报告「多次点击随机排座按钮,每隔一次出现完全相同排座」。

**根因**:`random-arrange.js` 中 3 处共用错误模式:
```js
const remainingStudents = state.students.filter(...);
shuffle(remainingStudents);                    // 返回新数组,原地不变!
placeStudentsInSeats(seats, remainingStudents); // 仍是 state.students 原顺序
```
主文件 `shuffle()`(seats-generator.js line 186)是「返回拷贝」非「原地修改」(`const a = [...arr]; return a;`),所以以上 3 处从未真正打乱。

**「每隔一次」的诡异表现**:
- 奇数次点击(1/3/5):上次 `prevSeatMap` 与本次填入的数组顺序**无冲突** → 后处理 swap 循环跳过 → 保留 `state.students` 原顺序 `[m0,m1,m2,m3,m4,f0,f1,f2,f3,f4]`
- 偶数次点击(2/4/6):大量学生仍在原座位 → 后处理 swap 重排 → 看似随机

**修复**:3 处全部改为 `const remainingStudents = shuffle(state.students.filter(...));`,分布在 random 模式 / mixed「剩余填充」/ samegender「剩余填充」三个分支。

**验证**:
- `node --check static/modules/random-arrange.js` 通过
- 自写 `.workbuddy/repro_random_bug.py`:8 次连点 random 全唯一(旧 bug 下奇数次都返回原序),相邻零重复
- `.workbuddy/repro_random_bug_modes.py`:mixed 5/5 唯一、samegender 5/5 唯一
- 既有 `.workbuddy/smoke_test_random_arrange.py`:4 场景 + dialog/console 错误检查 → 通过

**教训**:「shuffle 返回值」陷阱——任何 `shuffle(x); ...; use(x)` 模式都是 bug(除非 shuffle 是原地实现)。审计代码时直接 grep `shuffle(` 然后看返回值是否被使用。
