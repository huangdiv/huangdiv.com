## v1.4.7：同桌配对关联线走向统一（同日第三次迭代）

**需求**：「强制同桌」的关联线，已是同桌的两个座位有时在俩座位上方、有时在下方，保持统一。

**根因**：`pair-links.js#planOne()` 的 `sameRow` 分支用 `index % 2` 交替上/下走廊，
`index = links.length`（配对数组序号）⇒ 增删一组配对 / 导入顺序不同就翻面；
`off = ((index%5)-2)*jitter` 另有最多 3.2px 抖动。回退验证实测 y 17.4 ↔ 88.2。

**改动**（仅 `static/modules/pair-links.js`，UI / CSS 未动）
- 新增 `decideDeskmateSide(hLanes, rects)`：全班只按几何算一次侧别（顶行有上方走廊
  ⇒ 统一 `'above'`，否则 `'below'`），与配对顺序解耦。
- `planOne()` 以 `deskmateMap[fromIdx] === toIdx` 识别同桌：固定同侧走廊、`yA=yB`、
  不加 off；非同桌同行线保留 `index%2` 交错（避免长线重叠）。
- 返回 `deskmate` / `laneSide` 诊断字段；`planPairLinks` 把 `deskmateMap` 与
  `deskmateSide` 放进 ctx。用 deskmateMap 而非 `sameRow` 判定，顺带覆盖「同行座位
  高度略有差异 ⇒ 线一端上一端下」的隐患。
- 版本号 1.4.6 → 1.4.7（两处 APP_VERSION + HTML `?v=` + 两个静态 span）。

**测试**
- `unit_pair_links.mjs` 32→38 项（G 组 6 项）；`batch31` 34→39 项（17c 组 5 项，
  从真实 SVG path 反推走廊 y / above|below + 反转顺序后 d 不变）。
- 回退验证：`if (false && isDeskmate)` ⇒ G1/G2/G3/G4 红，还原后 38/38。
- 全量单测 14/14；batch31 39/39；回归 batch30 12/12、29 14/14、28 12/12、
  27 15/15、24 25/25、18 15/15、16 13/13、15 28/28、11 18/18、10 17/17、5 6/6。
- 顺带给 `batch11` 补 CDN 桩 + `domcontentloaded`（老批次裸 `goto()` 等 `load` 超时）。
- 视觉自检：`#classroom` 截图确认 4 条淡蓝线 + 1 条红虚线全部在座位上方、
  同排等高，× 在两座位中间上方，无压字 / 穿座。

**教训**：带语义的连线方位不能由遍历序号驱动；用户说「有时…有时…」先找隐藏的
顺序变量，并用「增删/改序后 d byte-for-byte 不变」的断言钉死。
