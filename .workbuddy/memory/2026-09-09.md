## BUG:教师视角拖拽后座位表「翻回学生视角」(commit 78d7d2d)
### 现象
教师视角拖学生后,讲台与切换按钮仍是教师视角,但**座位内容整个镜像翻转**,
拖放位置与目标颠倒。学生视角完全正常。

### 根因(索引语义混淆,很隐蔽)
- `seat-grid.js` 的 `fullRebuildSeats` 按 **DOM 追加顺序** `push` 进 `seatNodes`
- 教师视角下 DOM 追加顺序是**镜像**的(`resolveSeatCoord` 做了
  `rows-1-row / cols-1-col`),所以 `seatNodes[k]` 的 `data-index ≠ k`
- 但 `diffUpdateSeats` 把数组下标 `i` 当成 `state.seats` 的**真实索引**用
  (`state.seats[i]`),于是每次 diff 更新都按学生视角顺序重填学生
- 学生视角下 DOM 顺序恰好 == seatIndex,所以从不暴露 ⇒ 只在教师视角复现
- 触发面比拖拽更广:**任何 diff 更新**(签到打卡、分组着色、图标开关)都会翻

### 修复
`fullRebuildSeats` 改为以「真实座位索引」为下标写入
(`seatNodes[seatIndex] = seat`),DOM 追加顺序仍保持视觉镜像 —— 两者解耦。
恢复 `seatNodes[i] = seatIndex i` 这一既有注释契约(注释早写对了,实现没跟上)。

### 通用教训
「数组下标」与「业务索引」在**有镜像/排序/过滤变换的渲染里**必须显式区分:
要么存储按下标=业务索引,要么 diff 时从节点 `data-index` 反查。
写这类 persistent-DOM diff 时,先确认注释里的数组契约与实现是否一致。

### 测试有效性验证方法(值得复用)
修完不要直接交差 —— 临时把代码改回 buggy 写法跑一遍,确认新测试**真的会红**,
再改回来。本次回退后 5 项失败且报错信息正是「index 0 显示 s1 但 state 为空」,
证明断言抓到了真因,不是碰巧通过。

### 顺带加固
`dragdrop.js` 新增 `targetEl(e)`:拖拽事件 `e.target` 落在文本节点时是 `Text`,
没有 `closest()`,会抛 `e.target.closest is not a function` 中断整个 drop。
统一收敛成元素再取 `closest`(dragstart/dragenter/dragleave/drop 全覆盖)。

## 修复:下拉按钮一次点击即弹出 + 三个快捷按钮等高(commit 5634ca5)
### BUG 1:打印/PDF、智能排座下拉「有时要点两下」
- 根因:`setupActionDropdown` 的 `isOpen` 是闭包变量,两个下拉互斥关闭时
  **只改了对方的 style.display,没同步对方的 isOpen**。
  「A 开 → 点 B」后 A 的 isOpen 仍 true,下次点 A 执行 `setOpen(!true)` = 关闭
  ⇒ 必须再点一次。所以表现为「有时候」——取决于上一次操作的是不是另一个下拉
- 修复一:WeakMap 注册表(dropdown 元素 → controller),互斥关闭走对方 `close()`
- 修复二(双保险):翻转改为以 DOM 实际 display 为准
  `setOpen(dropdown.style.display !== 'block')`
- **通用教训:UI 开关状态用闭包变量维护时,任何「外部直接改 DOM」的路径都必须
  同步该变量,否则状态机失步。更稳的做法是让 DOM 成为唯一真相源**

### BUG 2:智能排座分段按钮 81px vs 切换模式/打印 78px
- 下段 padding 3/7 → 2/5(57+22-1=78)
- 更稳健:`.action-btn-wrapper > .action-btn` 改 `flex:1 1 auto` +
  `.action-btn-split-main` 设 `flex:1 1 auto` ⇒ 三者参与拉伸**自动等高**,
  不依赖写死像素(字体/内容变化也不失配)。实测三者均 78px,顶底边完全对齐
