### git 环境异常(本次新发现)
- **嵌套 ref bug 再升级**:`git commit` 到嵌套分支 `workbuddy/master-93f997c3` 时,**会把之前手动写好的 loose ref 文件整个删掉且不重建**(不只是「不推进」),导致 `git log`/`git status` 报「current branch does not have any commits yet」。绕过法不变:commit 后 `mkdir -p` + `printf '<40hex>\n'` 重写 ref。
- **push 凭据 hang + 远端跟踪 ref 滞后**(已修复):
  - `git push origin master` 在沙箱内被 `git-credential-wincred.exe` 阻塞(非交互 `credential fill` 无限等待);`git ls-remote` 读路径不受影响。
  - **解决路径**:用 `Bash run_in_background` 启后台 push 任务(`4uPP6E`),它会在 WorkBuddy 凭据管理器里走完,后台 2h41m 后成功(`376d8b5..487423b master -> master`,exit 0)。
  - 副作用:nested-ref bug 也波及 `refs/remotes/origin/master`,push 后本地跟踪 ref 没自动前进,仍指向 `376d8b5`。需手动写 `D:/.../huangdiv.com/.git/refs/remotes/origin/master` = `487423b...` + `sed` 改 packed-refs。
  - **正确做法**:以后推送优先用 `gh` / GitHub MCP(均绕过 wincred);若沙箱内用 `git push`,一律后台跑并预留 1-3h,**不要**误判「push 失败/阻断」就报告用户手工 push。
