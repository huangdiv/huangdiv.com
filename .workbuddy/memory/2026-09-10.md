
## 批次20:下拉菜单键盘焦点环与顶/底圆角协调(commit 74f684e,已推送)
- 问题:`.print-dropdown` 有圆角 + `overflow:hidden`,菜单项焦点环是矩形 inset 描边
  ⇒ 最顶/最底项聚焦时描边在圆角处被裁掉一块
- 方案:CSS 三处
  1. `.print-dropdown > *:first-child/:last-child` 继承容器圆角
     `calc(var(--radius-md) - 1px)`(=9px),上/下半各一;中间项保持矩形
  2. 菜单项焦点环改双层 inset:`inset 0 0 0 1px var(--surface), inset 0 0 0 3px var(--primary)`
     ⇒ 与容器 1px 边框留 1px 呼吸,且两层都跟随自身圆角
  3. `.dropdown-step-btn:focus-visible/:focus` 补 1px 主色内描边(跟随 6px 自身圆角),
     不再出现 UA 默认矩形蓝框;`.tag-suggestion-item` 焦点样式独立保留
- 新增 `.workbuddy/smoke_test_batch20_dropdown_focus_ring.py`(17 项),已做回退验证:
  把首项圆角改回 0px ⇒ 2 项转红,恢复后全绿
- 回归 batch5/11/18/19/e2e 全绿
- 测试编写坑:①下拉打开时第一项已 auto-focus,Tab 序列要先把当前 activeElement 记进来;

## 批次21:修复「男女不同桌/男女同桌」随机排座达成率低(commit 776ee3b,已推送)
- **根因**:`randomSeatArrange` 的「每位学生都不在原来座位」换座后处理(688-744 行循环)
  **完全无视性别规则**,把落座阶段排好的合规同桌大量拆散。回退实测:12 桌里最差 6 桌违规
  —— 与用户"很大机率排出的座位不符合要求"吻合
- **修复三处**(modules/random-arrange.js):
  1. 换座守卫 `swapBreaksGender(ci, si)`:试换后两侧同桌任一违规就不换。
     **优先级:性别规则 > 「必须换座」**(宁可个别学生留原位)
  2. 落座阶段 `placeStudentsGenderAware()`:剩余学生按「同桌单元」成组填,
     优先凑同性/一男一女;**分两轮填**(先每桌第一座、再回头填第二座)
     ⇒ 保证人人有座,留空只在人不够坐时发生(避免"为守规则而丢人")
  3. 收尾 `adjustGenderRuleInGroups({ mode })` 不传 areaOf ⇒ 全班范围修复残留;
     数学做不到(男/女人数为奇且满座)保留 + 新文案 `GENDER_RULE_UNSATISFIED`
- **测试**:新增 `static/tests/unit_gender_arrange_quality.mjs`(10 项,统计型:
  50/30 次重排 0 违规)+ `.workbuddy/smoke_test_batch21_*.py`(10 项,真实 UI 连点 10 次)
- **回退验证**:必须**同时**停掉守卫+收尾修复才会转红(只停守卫仍绿 ⇒ 收尾修复已兜住),
  7 项转红最差 6/12 桌违规。教训:写达成率测试时,要逐个禁用来定位"哪个改动才是关键"
- 单测 7 文件全绿;回归 batch9/11/13/15/19/e2e 全绿
