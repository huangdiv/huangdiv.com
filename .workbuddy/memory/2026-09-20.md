## 修复 workspace .git + 清理全部绕行产物(用户要求)
- **诊断**:workspace 是 worktree,`.git` 只是 72 字节指针
  (`gitdir: D:/Documents/GitHub/huangdiv.com/.git/worktrees/master-93f997c3`);
  但该管理目录已消失、原主仓也损坏(`HEAD` 歧义、`master 0000000`) ⇒ 所有 git 命令报
  `fatal: not a git repository: (NULL)`。
- **前置验证**:`diff -rq --strip-trailing-cr` 比对 workspace vs 健康 clone ⇒ **无任何独有内容**
  (仅 `.gitignore` 旧版 + 缺 `ClassMaster.html`) ⇒ 可安全替换。
- **修法**:备份坏指针到 `_cleanup_backup_seats_2026-09-20/git-pointer-broken/` →
  删指针文件 → 把 `_tmp_clone_huangdiv`(健康 clone,`ca93199`)的 `.git` 真目录 `cp -r` 过去
  → 补 `.gitignore` + `static/ClassMaster.html`。
- **行尾陷阱(踩了)**:换 index 后 `status` 报 **64 个 `M`**,但 `git diff` 为空、内容哈希全一致
  (= 纯 stat 脏)。根因:workspace 是**混合 CRLF/LF**(64 个 LF + 28 个 CRLF);
  `autocrlf=true` 会把 LF 判脏、`false` 又把 CRLF 判脏;克隆的 index 记的 size 还是 CRLF 尺寸(76658 vs 73014)。
  **解法**:本地 `git config core.autocrlf input` + `rm .git/index; git reset` 重建 ⇒ **零文件改写**,
  `porcelain count: 0`,`## master...origin/master` 无 ahead/behind。
- **嵌套 ref bug 精确刻画**(探针 `git update-ref` 实测,不再是"间歇"):
  - `refs/heads/<单段>` → **正常落盘**;`refs/heads/a/b` → 失败;
  - `refs/remotes/origin/<任意>` → **静默失败(exit 0 不落盘)**,且**删掉已存在的 loose ref 文件与空目录**;
    手工 `mkdir -p` 预置、甚至预置 loose 文件后再让 git 改写,都会被删。
  - ⇒ 结论:git 在本机**完全写不了 `refs/remotes/origin/*`**;`fetch`/`push` 后 `origin/master` 必滞后。
    稳妥同步只能改 `.git/packed-refs`(loose 会丢);主分支单段名 `master` 不受影响(提交正常)。
