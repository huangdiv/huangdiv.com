## v1.4.8 「按组聚座」改为每组按人数取最紧凑矩形

**需求**：点击「按组聚座」后，每组按自己的实际人数收拢到最聚集状态；6 人示例 =
1排1列 / 1排2列 / 2排1列 / 2排2列 / 3排1列 / 3排2列（即 3 行 × 2 列）；
判定可用「该组座位占据的总排数 + 总列数之和最小」，其他组依次类推。

**根因**：旧 `group-layout.js#chooseBlockShape(sizes,...)` 只按 `max(sizes)` 给**全班所有组**
定一个统一块，小组只能填块内前 n 格 ⇒ 6/4/2 时 4 人组变 `2×3`（span 5，2 空洞），
理论最优是 `2×2`（span 4）；7/4/1 时甚至变 `1×4`。且旧代价偏好「更宽」，6 人常给 `2×3`。

**改动**：
- `static/modules/group-layout.js` 整体重写（268 行）：新增 `chooseCompactShape(size,R,C)`；
  `planGroupSeatSlots(sizes,R,C,blocked)` 签名不变，改为逐组在全表枚举候选矩形
  `(r0,c0,bh,bw)`（`bw ∈ 1..min(C,n)`，`bh` 从 `ceil(n/bw)` 起最多 +2 行吸收占座空洞），
  矩形内 row-major 取前 n 个可用座位，用**这 n 个座位的真实外接矩形**打分
  `1000·span + 10·area + holes + 0.001·位置序号`。位置项只破平局 ⇒ 紧凑度永远优先，
  整体仍从左到右、从上到下。装不下时按到块中心距离就近补位并标 `layout.kind='sequential'`。
  返回 `layout.shapes[]` 逐组 `{groupIndex,size,rows,cols,span}`。
  紧凑度优先级：① 行数+列数最小 ② 面积/空位最少 ③ 更窄（6 人 → `3×2`）。
- `static/seats-generator.js`：toast 从「每组 X行×Y列」改为逐组摘要
  `已按分组聚座：N 个组，各组按人数收拢（6人:3行×2列、…）`；注释同步。
  `arrangeSeatsByGroup()` 的清人 / 就地写回流程**未动**。
- `static/seats-generator.html`：按钮 title 改为说明「最紧凑（总行数+总列数最小）」。
- 版本号四处同步到 `1.4.8`；`smoke_test_batch31` 的硬编码版本断言同步改为 1.4.8
  （历史性「v1.4.7 修复」注释保留）。

**测试**：

## v1.4.9 「按排名均衡分组」余数按组号倒序划归

**需求**：总人数不能被组数整除时，多出来的人按分组倒序划归 —— 排在前面的组不多人，
排在后面的组允许多 1 人。

**根因**：`student-rank.js#planBalancedGroupAssignment` 每批用
`slotOrder.slice(0, chunk.length)` 取目标组；满批时 `slotOrder` 按 `batch % 2` 正序/逆序
交替，但**最后不足一批**只取前 r 个 ⇒ 「谁多 1 人」取决于 `floor(N/G)` 的奇偶：
10 人 4 组（余数批 batch=2 偶数）→ `[3,3,2,2]`；14 人 4 组（batch=3 奇数）→ `[3,3,4,4]`。

**改动**（核心只一行）：
- `static/modules/student-rank.js`：`const isPartial = chunk.length < g;` +
  `const forward = !isPartial && batch % 2 === 0;` ⇒ 余数批恒取倒序 slotOrder 的前 r 个
  `[G-1 … G-r]`，整除时 `isPartial` 恒 false、蛇形一字未改。顶部设计要点与 JSDoc 同步。
- `static/seats-generator.js` 注释、`static/seats-generator.html` 主按钮 title、
  `static/modules/seat-grid.js` 分组模式 banner 按钮 title 同步说明规则。
- 版本号同步到 `1.4.9`；`batch31` / `batch32` 里的硬编码版本断言（docstring + 种子
  config.version + `check(version == ...)`）一并更新，否则回归会假红。
- 顺手修 E2E：连跑 14 个批次后 `goto` 30s 超时，重启服务无效 ⇒ 实测 html2canvas CDN
  响应约 10s（E2E 为真实导出 PNG 故意不桩它），把 `goto` 放宽到 90s、
  `wait_for_selector` 放宽到 30s 后恢复通过。

**测试**：
- `static/tests/unit_student_rank.mjs` 新增 H 组 8 项（31→39）：260 组 N/g 组合的精确人数
  不变量、偶数批反例、奇数批回归、`r=1` / `r=G-1`、整除时蛇形精确序列、前几个满批不受影响、
  余数名额恰在倒数 r 组、有性别班委时均衡优化不能挪走名额。

  奇数批 / 整除场景仍绿 ⇒ 测试精确钉死的是「余数方向」而不是「分组坏了」。

**经验**（已写入 ARCHIVE §3.15 / §5.2 / §5.4 / §6.1）：
