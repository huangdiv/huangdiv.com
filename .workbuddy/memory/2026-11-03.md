# 第五次迭代 —— 区域设置里的「当前满足情况」颜色提示(v1.4.1)

## 需求
区域设置弹窗中，已有设置项若**当前未满足**，给相应颜色提示（类似配对设置项）。

## 实现
- 判定：`currentZoneSeatMap()`（`currentSeats` + `seatZone` → `{sid:{index,zone}}`）
  + `zoneStudentStatus(student, at)` → `{status, prefBad, avoidBad, zone}`
  - `status = ''`（未设置，**不着色**）/ `ok` / `bad` / `na`（已设但未入座）
- 视觉沿用配对那套：`.zone-status-ok` 绿底 / `.zone-status-bad` 红底 / `.zone-status-na` 灰底，
  行内姓名同步染色（bad 加粗）；bad 时把**具体哪一栏**没满足的 `select` 加 `.zone-field-bad` 描红。
- `title` 说明「当前坐在「前中」 ✗ 没在倾向区域「后右」」，未入座则「尚未入座，暂无法判定」。
- 顶部汇总条 `.zone-status-line`：`当前座位:倾向 2/6 达成 · 避开 1/2 守住`（全达成加 ✓ 并转绿）；
  未入座的计入分母且算未达成。全无设置时 `hidden`。
- 刷新：打开时 / `change` 后 / `afterSeatsRender()` → `refreshZonePopupStatus()`。
- 就地刷新：`applyZoneRowStatus` 只改 class/title，不重建行 ⇒ 焦点留在刚操作的下拉上。

## 踩坑
1. `.zone-popup` 原本外壳与 `.zone-list` **双层滚动**：加了一行提示后末行被外壳切一半。
   改 `display:flex; flex-direction:column` + `.zone-list{flex:1 1 auto; min-height:120px}`，
   让列表吃满剩余高度。改完实测 `popH=518 popScroll=518`（外壳无滚动）、list 290>190 自己滚。
2. `activeZonePopup` 是文件后段的 `let` ⇒ 在 `afterSeatsRender` 里直接读会命中 TDZ，
   `typeof` 也抛 ⇒ 必须 try/catch（与 `refreshGenderHints` 同款兜底）。
3. Playwright 的 `select_option()` **不会**把焦点给 select（实测焦点仍在 `.zone-filter`），
   要验「刷新后焦点没丢」得先 `await sel.focus()`。
4. `autoSave()` 有 500ms 防抖 ⇒ 断言 localStorage 前至少等 700ms，否则读到旧值。

## 测试
- 新增 `smoke_test_batch28_zone_status.py`（12 项全通过）：ok / 倾向未达成 / 落在避开区 /
  两项都设只坏一项 / 未设置保持中性 / 未入座 na / title 文案 / 汇总条数字与 data-state /
  就地刷新且焦点保留 / 即时保存 / 智能排座后逐行与真实座位表核对 / 无 JS 报错。
- 回退验证：注释掉打开时的 `refreshZoneStatuses(popup)` ⇒ 7 项如期变红（status 全空、底色白），
  还原后 12/12。
- 回归：单测 12 文件全通过；batch27 15/15、batch25 17/17、batch26 9/9。

# 第六次迭代 —— 三个快捷按钮统一「上段执行 + 下段下拉」(v1.4.2)

## 需求
「模式切换」「打印/PDF」改成和「智能排座」一样的两段式：
- 模式切换：上段保持三态轮换，下段可直接选定某个模式；
- 打印/PDF：上段直接打印/另存为 PDF，下段选其他功能。

## 实现
- HTML：两个 wrapper 都换成 `.action-btn-split`（主按钮 + `.action-btn-split-caret`）。
  模式下拉 `#modeDropdown`（普通/签到/分组，data-action="mode" + data-mode），
  打印下拉删掉 `data-action="print"` 项，只剩 导出图片 / 导出 CSV。
- JS：`setupActionDropdown(btn, dropdown)` **去掉 peer 参数**，改用 `allDropdownCtrls` 登记表 +
  `closeAllDropdowns()`；点外部关闭也遍历登记表。新增 `applyMode()`、`doPrint()`；
  `updateModeSwitchButton()` 同步 `aria-checked` / `.active` / 「当前」胶囊。
- CSS：删掉 `.caret-placeholder`（已无人使用），新增 `.mode-menu-item[aria-checked="true"]`
  与 `.mode-menu-check`（「当前」胶囊）。

## 踩坑
1. 原先互斥是两两指名（print ↔ random），加第三个下拉必然漏掉一路 ⇒ 必须改成登记表。
2. 选中标记最初用 ✓，但「签到模式」的图标本身就是 ✓，两个 ✓ 分不清 ⇒ 改用「当前」文字胶囊。
3. 打印从菜单项上移到按钮后，下拉里出现「打印」自己一项会很怪 ⇒ 直接删项，并同步清理
   `if (action === 'print')` 分支。
4. 语义变了就必须改测试的**点击目标**（不能只改断言数字）：
   batch16（上段直接打印）、batch18（printBtn→printDropdownBtn，高度探针改比 `.action-btn-split`）、
   batch23、e2e_happy_path。

## 测试
- 新增 `smoke_test_batch29_split_buttons.py`（14 项全通过）：两段式结构、三组等高 78px、
  三处拼接无缝、上段直接打印（window.print 计数 1 且不展开）、下段一次点击即开、
  下拉只剩其他功能、上段轮换顺序 签到→分组→普通、当前项打勾（opacity 1/0）、
  下拉直选分组/签到/普通（含自动退出另一模式）、三下拉互斥、点空白收起、无报错。
- 回退验证：注释掉 `doPrint()` 与 `applyMode()` ⇒ 3 项如期变红，还原后 14/14。
- 回归：单测 12 文件通过；batch10 17/17、batch11 18/18、batch12 17/17（CDN 桩临时副本）、
  batch18 15/15、batch23 7/7、batch16 13/13、batch25 17/17、batch27 15/15、batch28 12/12。
