## 修复:随机排座后自动保存失效(别名断链)

### 症状
随机排座后界面显示新座位,但刷新回到旧座位 —— 用户感知"自动保存失效"。

### 根因:`currentSeats` 与 `state.seats` 别名断链
- `seats-generator.js:37` `let currentSeats = state.seats;`(顶层 let 别名,历史遗留,
  全文件 60+ 处引用,未整体迁移)
- **渲染** `modules/seat-grid.js` 读 `state.seats`
- **自动保存** `getCurrentConfig()` (seats-generator.js:240) 读 `currentSeats`
- `modules/random-arrange.js:101` 原为 `state.seats = Array(...).fill(null)` **重新赋值**
  → 打断别名 → 渲染读新数组、保存读旧数组 → 保存的是排座前的数据

### 修复(两处)
1. `random-arrange.js` 改**就地 `fill(null)`**(仅长度变化时才重建引用)—— 治本
2. `seats-generator.js` 的 `subscribe()` 回调开头加**别名回同步**:
   `if (state.seats !== currentSeats) currentSeats = state.seats;` —— 兜底,
   任何写点重新赋值 state.seats 都能自愈

### 相关上下文(前序批次)
- 批次 8 已把 `autoSave()` 从"各调用点手动调用"改为**订阅 `bus` 的 change 事件**,
  任何 `commit()` 都触发防抖保存 → 随机排座本已调 `commit({seats})`(random-arrange.js:370),
  所以问题不在"没触发保存",而在"保存的内容是旧的"
- 批次 8 另修:触摸 tap-move 路径原直接改 `currentSeats` + `generateSeats()`,
  未走 commit → 已改为 `commit({seats: currentSeats})`

### 排查手法(可复用)
渲染源 vs 持久化源不一致时,直接对比断言:
`localStorage.seats === state.seats`(烟测核心断言,修复前必然不等)

### 测试
- 新增 `.workbuddy/smoke_test_batch9_random_autosave.py`(9 场景全过)
  覆盖:8×8 渲染 / 两次排座基线 / **localStorage == state.seats** / 刷新持久化 /
  撤销也保存 / mixed+samegender 两模式
